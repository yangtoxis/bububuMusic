# 🔥 Хайповый музон

Discord-бот с общей музыкальной библиотекой сервера — «Хайповый музон» — и
личными плейлистами каждого пользователя, которые можно подмешивать в общий
эфир. Честный шаффл без повторов, полноценное DJ-управление и голосования
для всех остальных.

Библиотека наполняется как душе угодно: название, ссылка на трек или на
целый плейлист/альбом (YouTube, Spotify, Яндекс Музыка, SoundCloud), или
разом TXT-файлом на сотни треков. Бот сам находит трек, чистит его от
клипового мусора (скетчи, интро, самопромо — режется по SponsorBlock) и
кладёт в библиотеку под настоящим именем из источника.

## Что внутри

**🎵 Библиотека**
- `/add <название или ссылка>` — добавляет трек **или целый плейлист/альбом**.
  Понимает свободный текст и ссылки на YouTube / Spotify / Яндекс Музыку /
  SoundCloud — сам определяет, что ему дали, и одна ли это песня или список.
- `/import <file>` или ПКМ на сообщении с `.txt` → **Apps → Импортировать
  треки из TXT** — массовая загрузка списком (`Исполнитель — Название` на
  строку), фоново, не блокируя бота. По итогу — подробный отчёт: сколько
  добавлено, сколько уже было, что не удалось и почему.
- Дубликаты не скачиваются повторно — трек хранится один раз на диске и
  может одновременно состоять в общей библиотеке и в любом числе личных
  плейлистов. Названия и исполнители берутся из реальных метаданных
  источника, а не из того, что вы напечатали в поиске.
- Немузыкальные куски клипа (интро-скетчи, аутро, реклама) вырезаются
  автоматически через SponsorBlock, если для видео есть разметка.
- Ссылки на Spotify / Яндекс Музыку / SoundCloud читаются только ради
  открытых метаданных (название, исполнитель, список треков плейлиста) —
  сам звук всегда качается с YouTube, обхода DRM нигде нет.

**🎧 Личные плейлисты и режим «Микс»**
- `/playlist add <название или ссылка>` — добавить трек (или плейлист
  целиком) в свой личный плейлист, не трогая общую библиотеку.
- `/playlist import <file>` — то же самое, но TXT-файлом.
- `/playlist status` / `/playlist clear` — посмотреть или очистить свой
  плейлист.
- `/play mode:Микс` — DJ включает режим, в котором бот по очереди
  подмешивает треки из «Хайпового музона» и личных плейлистов **всех, кто
  сейчас в голосовом канале** (без плейлиста — просто не участвует в
  ротации). Заходит/выходит человек — состав ротации на лету пересчитывается.
  Один и тот же трек не повторится в сессии, даже если он есть в плейлистах
  сразу у нескольких людей.
- Привязка не по нику (ник можно сменить), а по Discord ID пользователя.

**🔀 Плеер**
- Честный шаффл: не повторяет только что сыгранный трек, старается не
  повторять исполнителя подряд, помнит последние сыгранные треки даже между
  `/stop` → `/play`.
- Материализованная очередь на 5 треков вперёд — `/queue`, с кнопкой
  перемешать; в режиме микса рядом с каждым треком видно, из чьего он
  плейлиста.
- Кнопки прямо под объявлением трека: ⏮️ / ⏹️ / ⏸️▶️ / ⏭️, громкость 🔉🔊,
  и ссылки на поиск трека на YouTube / Spotify / Яндекс Музыке с настоящими
  логотипами площадок.
- `/pause`, `/skip`, `/remove` (удалить играющий трек из того плейлиста, из
  которого он сейчас играет — с отменой одной кнопкой; из остальных
  плейлистов, где он тоже есть, трек не пропадает), `/add-queue` (поставить
  трек следующим без сохранения в чей-либо плейлист).

**🎛️ DJ и голосования**
- `/djrole add|remove|list` — любая роль (хоть несколько) даёт права DJ.
  Без настроенных ролей управлять может только «Управление сервером».
- DJ может всё: `/play`, `/stop`, `/skip`, `/pause`, `/volume`, кнопки на
  панели.
- Если DJ в канале нет — обычные пользователи запускают `/vote-start` или
  `/vote-stop`. Порог голосования — процент от числа людей в канале,
  настраивается через `/vote-settings`. Голосование живьём пересчитывается
  при входе/выходе людей из канала и сгорает по таймеру. Если в канал зашёл
  DJ во время голосования за включение — голосование отменяется, обход
  прав через толпу невозможен.

**🌍 Мультисервер**
Каждый сервер — своя независимая сессия: громкость, очередь, голосования,
подключение, режим (обычный/микс). Библиотека и личные плейлисты общие для
всех серверов, где стоит бот.

## Команды

| Команда | Кто | Что делает |
|---|---|---|
| `/add <track>` | DJ | Добавить трек или плейлист/альбом в библиотеку |
| `/import <file>` | DJ | Массовый импорт из TXT-файла в библиотеку |
| *ПКМ на сообщении → Импортировать треки из TXT* | DJ | То же, но из уже отправленного файла |
| `/add-queue <track>` | DJ | Поставить трек следующим, ни в какой плейлист не сохраняя |
| `/playlist add <track>` | все | Добавить трек/плейлист в свой личный плейлист |
| `/playlist import <file>` | все | То же TXT-файлом |
| `/playlist status` | все | Показать свой плейлист |
| `/playlist clear` | все | Очистить свой плейлист |
| `/library-status` | все | Статистика общей библиотеки |
| `/play [mode]` | DJ | Подключиться и запустить — «Хайповый музон» или «Микс» |
| `/stop` | DJ | Остановить и отключиться |
| `/pause` | DJ | Пауза / снять с паузы |
| `/skip` | DJ | Следующий трек |
| `/remove` | DJ | Удалить играющий трек из его плейлиста (с отменой) |
| `/queue` | все | Следующие 5 треков, DJ может перемешать |
| `/volume <0-100>` | DJ | Громкость, сохраняется на сервере |
| `/djrole add\|remove\|list` | Manage Server | Настройка ролей DJ |
| `/vote-settings` | Manage Server | Пороги голосований (%) |
| `/vote-start` / `/vote-stop` | все в канале | Голосование, когда DJ нет |

## Стек

Node.js 20+ · discord.js 14 · @discordjs/voice · better-sqlite3 · yt-dlp +
ffmpeg для скачивания и декодирования аудио.

## Запуск локально

```bash
npm install
cp .env.example .env   # заполнить DISCORD_TOKEN, CLIENT_ID, GUILD_ID
npm run deploy-commands
npm run dev
```

Нужны системные `ffmpeg` и `yt-dlp` в PATH.

## Деплой

Продовый вариант — Docker на VPS, `network_mode: host` (голосовому трафику
нужен прямой UDP), ffmpeg и yt-dlp ставятся в образ через apt/pip.

```bash
git clone https://github.com/yangtoxis/bububuMusic.git
cd bububuMusic
cp .env.example .env   # заполнить секреты, GUILD_ID оставить пустым в проде
docker compose up -d --build
docker compose exec bot node src/deploy-commands.js   # один раз, ~1ч на применение
```

## Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `DISCORD_TOKEN`, `CLIENT_ID` | credentials бота | — |
| `GUILD_ID` | dev-сервер для мгновенных команд, пусто в проде | — |
| `DB_PATH` | путь к SQLite | `./data/bot.sqlite` |
| `LIBRARY_DIR` | куда качаются треки | `./data/library` |
| `DEFAULT_VOLUME` | громкость по умолчанию | `70` |
| `DEFAULT_VOTE_START_PERCENT` / `DEFAULT_VOTE_STOP_PERCENT` | пороги голосований | `50` |
| `VOTE_TIMEOUT_SECONDS` | сколько живёт голосование | `60` |
| `IMPORT_TRACK_TIMEOUT_SECONDS` | таймаут на трек при импорте | `90` |
| `LOG_LEVEL` | `info` / `debug` | `info` |

## Модель данных плейлистов

Трек и его файл на диске хранятся один раз. Принадлежность к плейлисту —
отдельная связь многие-ко-многим: один и тот же трек может одновременно
быть в общей библиотеке и в личных плейлистах нескольких людей. Удаление
трека из одного плейлиста не трогает остальные — трек физически удаляется
с диска только когда его больше не осталось ни в одном плейлисте.

## Ограничения

Без DRM-обхода — весь звук идёт через штатное скачивание yt-dlp с YouTube.
Ссылки на Spotify / Яндекс Музыку / SoundCloud используются только для
чтения открытых метаданных (название, исполнитель, список треков) — сам
файл всегда берётся с YouTube. VK Музыка не поддерживается — сервис не
отдаёт даже базовые метаданные без авторизации пользователя, а заводить
OAuth ради этого сознательно не стали (та же причина, по которой нет
Spotify OAuth). Публичный скрейпинг отдаёт только первую часть очень
больших плейлистов Spotify (страница отдаёт ограниченный список сама).
